# 项目简介

## 简短版本

migrator 是一个在任意两台 Linux 主机之间执行整机迁移的工具。迁移以一份可以审核的文本计划为中心，计划由两端的只读状态生成。工具按计划重建目标磁盘布局，复制文件系统与数据，修正引导与网络配置，验证可启动后执行切换。源主机磁盘全程只读。

## 短版（约 100 字）

migrator 用于在任意两台 Linux 主机之间迁移完整系统。它先读取两端并生成可编辑的迁移计划，再重建目标磁盘、复制文件、修正引导与网络，验证通过后完成切换。支持在线增量与离线复制，源主机磁盘不被写入，不绑定特定云平台。

## 长版

migrator 解决的是服务器整机迁移问题。一台 Linux 主机需要更换硬件、迁移到新机房，或迁移到另一台虚拟机时，目标是在不重装系统、不手工重建分区与服务的前提下完成迁移，并保证新系统能够直接启动。

工具的工作分为八个阶段：

1. **清单**：只读采集源端与目标端的磁盘、分区、md RAID、LVM、文件系统、网络和操作系统信息。
2. **计划**：根据两端状态生成计划文件，记录目标分区表、LVM 命令、格式化参数、每个卷的复制方式、fstab 标识改写、网络与固件决策。
3. **检查**：重新校验计划与当前清单、目标磁盘几何、卷容量是否一致。检查不通过时不会写入磁盘。
4. **写入**：清空并重建目标盘布局，创建 md 与 LVM，格式化，并校验新文件系统的特性掩码与源端一致。
5. **传输**：块级卷按文件系统镜像复制，文件级卷按目录树复制。在线模式通过多轮增量缩小冻结窗口。
6. **修补**：在目标系统 chroot 中修正 fstab、mdadm、LVM、内核命令行、initramfs、GRUB、网络与 cloud-init。
7. **验证**：以只读方式检查引导项、initramfs、fstab、内核命令行、文件系统特性、引导器、网络与 RAID；可选使用 QEMU 叠加盘试启动。
8. **切换**：将源端移出网络，确认其离线后启动目标端。

该工具的设计重点是可控性：

- 迁移计划是文本文件，可以在写入磁盘前完整审核；
- 源端磁盘不被写入，可作为回滚依据；
- 目标盘写入前执行指纹校验，防止计划生成后磁盘被替换；
- 验证未通过时拒绝切换；
- 切换前确认源端离线，避免两台主机同时使用同一 IP。

支持的迁移模式：

- **离线迁移**：两端均启动到迁移 Live，每个卷复制一次，逻辑简单。
- **在线迁移**：源端继续运行，通过 eBPF 或 ftrace 记录写入，多轮增量后短暂冻结，完成末轮复制。
- **中继迁移**：两端位于 NAT 后时，通过第三台主机转发控制与数据通道。

支持范围包括 Debian、Ubuntu、CentOS、Rocky Linux、AlmaLinux 与 RHEL，ext2/3/4 与 XFS，MBR/GPT，LVM，md RAID，BIOS 与 UEFI 的双向切换。不支持 btrfs、ZFS、LUKS、NTFS、Windows、SUSE 与 grub-legacy 系统。

适用对象：

- 需要更换服务器硬件但保留系统的运维团队；
- 需要把物理机迁移到虚拟机、或把虚拟机迁移到物理机的环境；
- 需要在不同云平台或不同机房之间迁移，但不希望绑定厂商迁移服务；
- 需要对迁移过程进行审核、验证与回滚的生产环境。

当前限制：

- 目标磁盘容量不小于 20 GiB；
- 一个 LVM 卷组只能位于一个物理卷；
- 目标端 Secure Boot 仅在源端为 UEFI 且有 shim 时可用；
- 网络配置保留源端 IP，跨网段迁移后需要人工调整；
- 增量传输可跨越传输进程的中断；任一端整机重启后需要重新开始。
