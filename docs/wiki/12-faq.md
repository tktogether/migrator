# 常见问题

## 迁移会写入源主机吗？

源主机的磁盘数据不会被写入。离线模式中源主机运行 Live，原磁盘不被挂载；在线模式中源磁盘以只读方式读取，agent 仅记录块写入。

在线模式会修改源主机的两处运行环境：

- 向 root 的 `authorized_keys` 追加一次性会话公钥；
- 在 `/run` 下创建一个临时 agent 程序。

这两项不涉及源磁盘数据。会话公钥不会自动删除，需要时手工清理。

## 停机时间有多长？

- **离线模式**：从源主机离开原系统到目标系统启动完成。数据传输时间包含在内。
- **在线模式**：仅文件系统冻结窗口。窗口长度取决于末轮增量、链路速率与目标端写入速度，不是固定值。

在线模式在冻结前会尽可能增加增量轮次，以减少冻结时的剩余数据量。若增量无法收敛，工具不会提前冻结。

## 目标磁盘可以比源磁盘小吗？

可以，但受复制方式限制：

- 块级复制要求目标卷不小于源卷；
- 文件级复制要求目标卷不小于“已用空间 × 1.10 + 512 MiB”；
- 根文件系统可用 `-o root=files` 强制文件级复制；
- 非根块级卷无法缩小，除非调整其复制方式或目标布局。

目标磁盘小于源磁盘时，分区表会按目标磁盘重新布局。源端多块磁盘的内容会作为额外槽位追加到目标盘。

## 目标磁盘可以比源磁盘大吗？

可以。计划会把剩余空间分配给弹性槽位，通常是承载根文件系统或最大文件系统的槽位。复制完成后执行扩容：

- ext2/3/4 使用 `resize2fs`；
- XFS 使用 `xfs_growfs`。

## 支持多块源磁盘吗？

支持。源端主磁盘之外的、带有文件系统、swap 或 PV 的分区，会作为额外槽位追加到目标磁盘。源端 md 阵列与 LVM 卷组按卷迁移。

限制：一个卷组必须位于一个物理卷上，不能跨多个 PV 或磁盘。

## 支持多块目标磁盘吗？

两种方式：

- 使用 `-d` 指定其中一块作为目标盘；其它磁盘保持只读；
- 使用 `-o raid=1 -d DISK,DISK2` 将两块磁盘组成按槽位的 md RAID1。

RAID1 仅支持 deb 系源系统。两块盘容量不同时，按较小盘布局，较大盘的剩余空间不使用。

## 支持 LVM 与 md RAID 吗？

支持：

- LVM 卷组、逻辑卷、swap 逻辑卷；
- LVM on md；
- md RAID 源布局；
- 目标端新建 md RAID1（`-o raid=1`，仅 deb 系）。

不支持卷组跨多个 PV。

## 支持跨固件迁移吗？

支持 BIOS→UEFI 与 UEFI→BIOS，deb 系与 rhel 系均有实现路径：

- deb 系从迁移 Live 安装目标固件的 GRUB；
- rhel 系在目标 chroot 中通过 dnf 安装对应 GRUB 软件包。

目标端启用 Secure Boot 时，源端必须是 UEFI 且 ESP 上有 shim。源端为 BIOS 时计划会拒绝。

## 支持哪些文件系统？

源文件系统支持 ext2、ext3、ext4、XFS。目标端还会创建 vfat ESP 与 swap。

不支持 btrfs、ZFS、LUKS、NTFS、F2FS、reiserfs。

## 支持 Windows、SUSE、Arch Linux 吗？

不支持。当前范围为 Linux 源系统，deb 系与 rhel 系。

## 支持 ARM 或 32 位系统吗？

不支持。迁移环境与 agent 面向 x86_64。

## 可以在运行中的目标系统上执行吗？

不可以。迁移命令要求完整迁移 Live，因为 apply 会清空目标盘、重建分区、格式化并挂载目标系统。在运行中的系统上执行会破坏当前系统。

`tools/install.sh` 可以把工具安装到任意系统，但迁移命令本身仍要求 Live。

## 失败后可以从中断处继续吗？

可以，但有限制：

- 同一次 Live 运行内，已完成的卷会跳过，已写入且指纹未变的目标盘不会再次清空；
- 失败阶段可以单独重试；
- `-o redo=` 可重做指定卷；
- 传输进程中断后，可以依靠续传记录继续，前提是源端会话仍然存在；
- 任一端整机重启后，计划与续传记录随内存丢失，需要重新开始。

## 如何回滚？

- **离线模式**：源端磁盘从未被写入。将目标端离线，重新启动源端即可。
- **在线模式，尚未切换**：执行 `migrator -o cutover=rollback -s cutover` 解冻源端。
- **在线模式，已经切换**：先确保目标端离线，再启动源端。源端磁盘仍是迁移前的数据。
- **目标端已写入但未切换**：源端不受影响；目标端可以保留作为副本，或重新执行迁移。

## 会保留哪些内容？

- 文件系统内容与属性；
- 服务、systemd 单元、定时任务；
- 容器镜像与容器数据（作为文件复制）；
- 数据库数据文件；
- 网络配置（网卡名与 MAC 除外）；
- 用户、权限、ACL、SELinux 标签；
- swap 分区、swap 逻辑卷与 swap 文件。

运行期状态不保留，例如：

- 内存中的进程状态；
- 未写入磁盘的临时数据；
- `/run`、`/proc`、`/sys` 内容；
- Docker 运行中的容器状态（容器会按 restart 策略重新启动）。

## 迁移后 IP 会变吗？

工具保留源系统的 IP、网关和 DNS 配置，只改网卡名称与 MAC。

- 源端使用 DHCP：目标端在新网络中重新获取地址；
- 源端使用静态地址且目标端位于同一网段：沿用原地址，切换后源端离线，不会冲突；
- 源端使用静态地址且目标端位于不同网段：迁移后需要手工修改。

## 传输加密吗？

- 离线默认 `data=ssh`：数据经 SSH 加密；
- 在线：agent 通过 SSH 会话传输，数据帧可选用 zstd 压缩；
- `data=raw`：使用 busybox `nc`，不加密，仅适用于可信局域网。

## 如何查看进度？

- 完整日志：`/run/migrator/log`
- 在线 agent 输出：`/run/migrator/online.out`
- 单卷日志：`/run/migrator/vol-N.log`
- 当前状态：`cat /run/migrator/state`
- 失败原因：`cat /run/migrator/failure`
- 重新连接 tmux：`migrator -s attach`

## 日志会保留吗？

`/run` 是内存文件系统，重启后丢失。验证通过后，计划、日志、状态与清单会复制到目标系统的 `/root/migrator-<日期>/`。

需要长期保留时，在重启前复制 `/run/migrator`。

## cloud-init 会被保留吗？

默认禁用它重新配置网络与主机名，写入 `/etc/cloud/cloud.cfg.d/99-migrator.cfg`。使用 `-o cloudinit=keep` 可保留原行为。

## 为什么目标系统启动后没有网络？

常见原因：

- 目标网卡名称与配置不一致；
- 配置仍引用源端 MAC；
- 静态 IP 不适用于目标网段；
- 防火墙规则引用了旧网卡名。

验证摘要会给出 MAC 与预期网卡名的对应关系。需要时通过 BMC 控制台登录并调整配置。

## 为什么冻结后无法 SSH 登录源端？

源端根文件系统处于冻结状态。SSH 登录会在 PAM 写入 `wtmp` 时阻塞，表现为认证通过但命令不执行。

应使用 `cutover` 或 `cutover=rollback`。若目标端无法联系源端，可在源端控制台执行 `fsfreeze -u /`。

## 版本号如何确定？

仓库中的 `VERSION` 文件为 `1.2`，表示派生自 reloca.to 1.2。实际安装版本由 `git describe --always --dirty` 决定；没有 Git 信息时回退到 `VERSION` 文件。
