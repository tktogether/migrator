# reloca.to

[English](README.md) · **Українська** · [Русский](README.ru.md)

Переносить встановлений Linux-сервер з однієї машини на іншу мережею однією
командою. Це не образ диска і не бекап: утиліта читає обидві машини, пише план,
який можна прочитати і виправити, розмічає нові диски з тими самими UUID,
копіює кожну файлову систему, доробляє копію в chroot (fstab, mdadm, драйвери в
initramfs, grub, мережа), перевіряє, що вона завантажиться, і лише потім
перемикає. **Старий сервер лише читається.**

```sh
curl -fsSL reloca.to | bash      # на новому сервері, завантаженому в Live OS
reloca.to root@10.0.0.12         # адреса старого
```

Зроблено в [XServer](https://xserver.cloud/) для власних переїздів між
дата-центрами, потім віддано всім: <https://reloca.to/uk/>.

## Два режими

**Off-line relocation.** Обидві машини працюють у Live OS. Кожен том копіюється
один раз, настільки швидко, наскільки дозволяють диски й канал. Сервер не
обслуговує з моменту виходу зі своєї системи і доки не завантажиться новий.

**On-line relocation.** Старий сервер лишається у своїй системі й працює далі.
`reloca-agent` копіює томи просто під записом і стежить за кожним записом по
ходу; прохід за проходом переїжджають лише змінені блоки, доки те, що
лишилося, не передаватиметься кілька секунд. Тоді файлові системи морозяться
рівно на ці секунди, переїжджає остання дельта, і новий сервер підіймається.
Виміри на стенді із заданим каналом:

| канал | перший прохід | збіжність | вікно заморозки | весь переїзд |
|---|---|---|---|---|
| 10 GbE | 15 с, 147 МіБ/с | на третьому проході | 1.7 с | 223 с |
| 400 Мбіт, 20 мс | 41 с, 66 МіБ/с | на четвертому проході | 8.7 с | 341 с |
| 100 Мбіт, 30 мс, 0.05% втрат | 185 с, 14.9 МіБ/с | не збігається | 100 с | 953 с |

Третій рядок — це випадок, коли сервер пише швидше, ніж канал забирає дані.
Агент міряє обидві швидкості, передбачає, що дельти не зменшаться, і каже про
це замість того, щоб молотити даремно: або бере те вікно, яке є, або
відмовляється морозити взагалі, лишаючи старий сервер недоторканим.

## Чого утиліта ніколи не робить

- Не пише на старий сервер: ні fsck, ні resize. Він лишається точкою відкату.
- Не стирає диск, доки ви не прочитаєте, що на ньому зараз, і не введете його
  ім'я та розмір з екрана.
- Не форматує «за замовчуванням»: кожна файлова система створюється з
  можливостями джерела і звіряється одразу після mkfs.
- Не перезавантажує новий сервер без зеленої перевірки.
- Не чіпає інші диски нового сервера.

## Що підтримується

| | |
|---|---|
| Вихідні системи | Debian 10–13, Ubuntu 18.04–26.04, CentOS 7–10, Rocky / Alma / RHEL 8–10 |
| Розмітка | md RAID будь-якого рівня, LVM, LVM на md, звичайні розділи MBR і GPT |
| Файлові системи | ext2/3/4, XFS; swap-розділи, логічні томи і swap-файли; ESP |
| Прошивка | BIOS → BIOS, UEFI → UEFI і UEFI ↔ BIOS в обидва боки |
| Диски | новий диск може бути більшим або меншим за старий |
| Мережа | ifupdown, netplan, systemd-networkd, ifcfg, NetworkManager |

Не підтримуються btrfs, ZFS, LUKS, NTFS, CentOS 6 та інші системи на
grub-legacy, SUSE, Windows.

On-line режиму потрібні ще root на працюючому сервері та ядро, здатне
відстежувати записи: eBPF там, де він є, і ftrace аж до 3.10 з CentOS 7.

## Фази

Кожну можна запустити окремо через `-s`; зроблене пропускається, тому фазу, що
впала, можна повторити.

```sh
reloca.to -s plan root@10.0.0.12   # лише читання: інвентар обох сторін і план
$EDITOR /run/reloca.to/plan        # за бажанням виправити
reloca.to -s check                 # перевірка виправлень
reloca.to -s apply                 # розмітка, LVM, swap, mkfs (спитає перед записом)
reloca.to -s transfer              # передача томів
reloca.to -s postfix               # chroot: fstab, mdadm, initramfs, grub, мережа
reloca.to -s verify                # десятки перевірок; код 3 означає «не перезавантажувати»
reloca.to -s cutover               # старий сервер з мережі, новий вантажиться
```

`reloca.to -n` — сухий прогін: друкує план і кожну команду і не змінює нічого на
жодній із машин.

## Опції

Усі прапорці, фази і ключі `-o` зібрані на <https://reloca.to/uk/options/> та в
`reloca.to -h`. Опції передаються по одній, бо кома належить значенню:

```sh
reloca.to -o compress=none -o converge=5 root@10.0.0.12
```

## Збірка з джерел

```sh
make test         # shellcheck і табличні тести: секунди, без root
make agent        # статичний агент (потрібні компілятор C і libzstd)
make agent-test   # агент на loop-пристроях цієї машини (потрібен root)
make install      # у /usr/local, або PREFIX=/opt/reloca make install
```

Сама утиліта — це bash із підключеними бібліотеками; агент (`agent/`) — один
бінарник на C, якому під час роботи нічого не потрібно. Посібник оператора і
[довідник опцій](https://reloca.to/uk/options/) лежать на
<https://reloca.to/uk/> трьома мовами. Вони живуть там, а не в репозиторії,
бо саме туди викладається кожен випуск: так посібник завжди описує поточну
версію.

## Якщо переїзд пішов не так

Відкрийте issue і додайте план (`/run/reloca.to/plan`), лог
(`/run/reloca.to/log`) і те, що сказала перевірка. Нестандартна розмітка і старі
дистрибутиви — саме те, від чого утиліта стає кращою, а старий сервер у
будь-якому разі лишається недоторканим, тож є з чим порівняти.
