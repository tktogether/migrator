# reloca.to

[English](README.md) · [Українська](README.uk.md) · **Русский**

Переносит установленный Linux-сервер с одной машины на другую по сети одной
командой. Это не образ диска и не бэкап: утилита читает обе машины, пишет план,
который можно прочитать и поправить, размечает новые диски с теми же UUID,
копирует каждую файловую систему, дорабатывает копию в chroot (fstab, mdadm,
драйверы в initramfs, grub, сеть), проверяет, что она загрузится, и только потом
переключает. **Старый сервер только читается.**

```sh
curl -fsSL reloca.to | bash      # на новом сервере, загруженном в Live OS
reloca.to root@10.0.0.12         # адрес старого
```

Сделано в [XServer](https://xserver.cloud/) для собственных переездов между
дата-центрами, потом отдано всем: <https://reloca.to/ru/>.

## Два режима

**Off-line relocation.** Обе машины работают в Live OS. Каждый том копируется
один раз, настолько быстро, насколько позволяют диски и канал. Сервер не
обслуживает с момента выхода из своей системы и пока не загрузится новый.

**On-line relocation.** Старый сервер остаётся в своей системе и продолжает
работать. `reloca-agent` копирует тома прямо под записью и следит за каждой
записью по ходу; проход за проходом переезжают только изменившиеся блоки, пока
оставшееся не будет передаваться считаные секунды. Тогда файловые системы
морозятся ровно на эти секунды, переезжает последняя дельта, и новый сервер
поднимается. Замеры на стенде с заданным каналом:

| канал | первый проход | сходимость | окно заморозки | весь переезд |
|---|---|---|---|---|
| 10 GbE | 15 с, 147 МиБ/с | на третьем проходе | 1.7 с | 223 с |
| 400 Мбит, 20 мс | 41 с, 66 МиБ/с | на четвёртом проходе | 8.7 с | 341 с |
| 100 Мбит, 30 мс, 0.05% потерь | 185 с, 14.9 МиБ/с | не сходится | 100 с | 953 с |

Третья строка это случай, когда сервер пишет быстрее, чем канал уносит данные.
Агент меряет обе скорости, предсказывает, что дельты не уменьшатся, и говорит об
этом вместо того, чтобы молотить вхолостую: либо берёт то окно, которое есть,
либо отказывается морозить вообще, оставляя старый сервер нетронутым.

## Чего утилита никогда не делает

- Не пишет на старый сервер: ни fsck, ни resize. Он остаётся точкой отката.
- Не стирает диск, пока вы не прочитаете, что на нём сейчас, и не введёте его
  имя и размер с экрана.
- Не форматирует «по умолчанию»: каждая файловая система создаётся с фичами
  источника и сверяется сразу после mkfs.
- Не перезагружает новый сервер без зелёной проверки.
- Не трогает другие диски нового сервера.

## Что поддерживается

| | |
|---|---|
| Исходные системы | Debian 10–13, Ubuntu 18.04–26.04, CentOS 7–10, Rocky / Alma / RHEL 8–10 |
| Разметка | md RAID любого уровня, LVM, LVM на md, обычные разделы MBR и GPT |
| Файловые системы | ext2/3/4, XFS; swap-разделы, логические тома и swap-файлы; ESP |
| Прошивка | BIOS → BIOS, UEFI → UEFI и UEFI ↔ BIOS в обе стороны |
| Диски | новый диск может быть больше или меньше старого |
| Сеть | ifupdown, netplan, systemd-networkd, ifcfg, NetworkManager |

Не поддерживаются btrfs, ZFS, LUKS, NTFS, CentOS 6 и другие системы на
grub-legacy, SUSE, Windows.

On-line режиму нужны ещё root на работающем сервере и ядро, умеющее отслеживать
записи: eBPF там, где он есть, и ftrace вплоть до 3.10 из CentOS 7.

## Фазы

Каждую можно запустить отдельно через `-s`; сделанное пропускается, поэтому
упавшую фазу можно повторить.

```sh
reloca.to -s plan root@10.0.0.12   # только чтение: инвентарь обеих сторон и план
$EDITOR /run/reloca.to/plan        # при желании поправить
reloca.to -s check                 # перепроверка правок
reloca.to -s apply                 # разметка, LVM, swap, mkfs (спросит перед записью)
reloca.to -s transfer              # передача томов
reloca.to -s postfix               # chroot: fstab, mdadm, initramfs, grub, сеть
reloca.to -s verify                # десятки проверок; код 3 значит «не перезагружать»
reloca.to -s cutover               # старый сервер с сети, новый грузится
```

`reloca.to -n` — сухой прогон: печатает план и каждую команду и не меняет ничего
ни на одной из машин.

## Опции

Все флаги, фазы и ключи `-o` собраны на <https://reloca.to/ru/options/> и в
`reloca.to -h`. Опции передаются по одной, потому что запятая принадлежит
значению:

```sh
reloca.to -o compress=none -o converge=5 root@10.0.0.12
```

## Сборка из исходников

```sh
make test         # shellcheck и табличные тесты: секунды, без root
make agent        # статический агент (нужны компилятор C и libzstd)
make agent-test   # агент на loop-устройствах этой машины (нужен root)
make install      # в /usr/local, или PREFIX=/opt/reloca make install
```

Сама утилита — это bash с подключаемыми библиотеками; агент (`agent/`) — один
бинарник на C, которому во время работы ничего не нужно. Руководство оператора
и [справочник опций](https://reloca.to/ru/options/) лежат на
<https://reloca.to/ru/> на трёх языках. Они живут там, а не в репозитории,
потому что туда выкладывается каждый выпуск: так руководство всегда описывает
текущую версию.

## Если переезд пошёл не так

Откройте issue и приложите план (`/run/reloca.to/plan`), лог
(`/run/reloca.to/log`) и то, что сказала проверка. Нестандартная разметка и
старые дистрибутивы — именно то, от чего утилита становится лучше, а старый
сервер в любом случае остаётся нетронутым, так что есть с чем сравнивать.
